- `src/lib/calendar-sync-load.ts`: new `listOccurrenceIdsToBackfill(db, professionalId, now, limit)`. Ids of the pro's occurrences with `status = 'scheduled'`, `starts_at > now` and at least one `confirmed` booking of the same pro (uncorrelated `inArray` sub-select, so no outer column is interpolated into it: the drizzle 0.45 single-table trap does not apply). Ordered by `starts_at, id`, limited. Séances and RDV go through the same rule. A pending hold (live or lapsed), a cancelled booking and a cancelled occurrence never qualify. A marker already stored does not exclude an occurrence: the sync is idempotent, and a marker left by a run in flight at a disconnect would otherwise hide the occurrence from the new calendar (a PATCH of a marker unknown to the new calendar falls back to the insert).
- `src/lib/calendar-backfill.ts` (pure, no db, no next/*): `backfillGoogleWith(professionalId, deps)`. Asks for 201 ids, syncs at most `BACKFILL_MAX = 200` (soonest first), waits `BACKFILL_GAP_MS = 300` between two occurrences that called Google (no pause after `noop` / `skipped` / `disabled`, none before the first or after the last), counts failures, logs one line « [calendar-sync] backfill for pro <id>: N occurrence(s) processed[, K failed][, more remain (the next changes sync them)] » and never throws (an id read failure or a thrown sync is caught and logged through `logSafeMessage`, so no address reaches the log).
- `src/server/google-backfill.ts` (server-only): `scheduleGoogleBackfill(professionalId)` = `after(() => runGoogleBackfill(professionalId))` wrapped in try/catch; `runGoogleBackfill` wires the real deps (`listOccurrenceIdsToBackfill(db, ...)`, the existing `syncOccurrence`, a `setTimeout` sleep, console).
- `src/server/pro.ts` `finalizeGoogleConnection`: after the calendar id is stored (outside the try that answers « Connexion à Google impossible. »), calls `scheduleGoogleBackfill(pro.id)`. The pro id comes from the session (`getCurrentProfessional`), never from input. Only the fresh-connection path schedules it: the « already connected » early return is untouched, so reloading the settings page never re-runs it.
- `src/lib/calendar-sync.ts`: `syncOccurrence` now returns its `SyncOutcome` (or `"failed"` after logging) instead of `void`, so the backfill can count failures and skip the pause when no Google call was made. Existing caller (`notify.ts`) ignores the value.
- `clearGoogleLink` doc comment no longer says « Nothing is backfilled ».

Not verified by hand against the real Google API (same carry as the ledger Task 4 note on the deterministic id in a fresh calendar).
